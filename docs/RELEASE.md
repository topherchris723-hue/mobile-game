**Application ID choice (round 7):** `com.animecardbattler.game` is deliberately **title-neutral**. The title
"Jade Tempest" is cleared for the internal testing track only (STATUS, round 7) and may still change after legal
clearance. The application ID **can never change after the first upload to Play Console**, even on the internal
track. A title-neutral ID means a later title switch only needs a new `appName`. To pick a different ID, change it
**before the first upload** in `capacitor.config.json`, `android/app/build.gradle` (`namespace`, `applicationId`),
`res/values/strings.xml` and the `MainActivity.java` package/folder.

**Target SDK requirement:** Google Play says that since **2026-08-31**, new apps and app updates must target
**Android 16 (API 36)** or higher. Checked on developer.android.com/google/play/requirements/target-sdk on
**2026-10-24**. Check this again before every release. `android/tools/check-identity.mjs` holds the minimum as
`MIN_TARGET_SDK`.

## 2. Versions

`versionName` is `MAJOR.MINOR.PATCH` and equals `package.json` `version`. `versionCode` must go up for every upload
to Play, on any track. Both live in `android/app/build.gradle`. Bump them **before** the release review, because
the release gate rejects any change to `android/` after the reviewed commit. Newest row first. `npm run android:check`
compares the newest row with `build.gradle`.

## 3. Build a debug APK (any time, no review needed)

A debug APK is signed with Android's throw-away debug key, not the upload key. Use it only for testing. It cannot
be uploaded to Play.

**On GitHub (recommended):** Actions → *Build Android* → *Run workflow* → `build_type: debug`. The job runs
`npm ci`, `npm test`, `npm run build`, checks the app identity, builds `app-debug.apk`, checks the merged manifest
with `aapt` (only VIBRATE allowed), prints the size and the largest files, and uploads the artifact
`app-debug-<sha>`.

**Locally** (needs JDK 21 and an Android SDK with `platforms;android-36` and `build-tools;36.0.0`, with
`ANDROID_HOME` set):

```bash
npm ci
npm run android:check            # source identity check (no SDK needed)
npm run android:debug            # build web → cap sync → gradlew assembleDebug
AAPT=$ANDROID_HOME/build-tools/36.0.0/aapt node android/tools/check-identity.mjs \
  --apk android/app/build/outputs/apk/debug/app-debug.apk   # merged-manifest check
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

On the phone, check these: the icon and the name "Jade Tempest", the splash, that the game boots **with Wi-Fi and
mobile data off**, portrait lock, and that haptics vibrate.

Other scripts: `npm run cap:sync` (build and copy into `android/`), `npm run android:icons` (regenerate every icon PNG;
needs the Playwright Chromium and ImageMagick `convert` for the 32-bit Play icon). The `android/` project
is committed. Do **not** run `npx cap add android` again, because it brings back the template icon and the INTERNET
permission.

## 4. Release build (only after `VERDICT: PASS` on the same commit)

1. `reports/release-review.md` ends with `VERDICT: PASS` and has a line `Commit: <40-char sha>`.
2. Actions → *Build Android* → `build_type: release` (or push a tag `v0.1.0`). The gate checks the verdict, that the
   reviewed commit is in the history, and that `src data assets index.html styles package.json package-lock.json
   capacitor.config.json android` have not changed since that commit. Then it builds, signs and verifies
   `app-release.aab` (for Play) and `app-release.apk`, and runs the identity check on the signed APK.
3. Download the artifact `app-release-<ref>-<sha>`.

## 5. Owner steps (CLAUDE.md §8). Only the owner does these, once, before the first release

**a. Create the upload keystore** on your own computer (JDK `keytool`). Never put it in the repo:

```bash
keytool -genkeypair -v -keystore jade-upload.jks -storetype JKS \
  -alias upload -keyalg RSA -keysize 2048 -validity 10000
# keytool asks for a keystore password, a key password and your name/organisation.
base64 -w0 jade-upload.jks > jade-upload.jks.b64     # macOS: base64 -i jade-upload.jks -o jade-upload.jks.b64
```

Back up `jade-upload.jks` and both passwords offline, in two places. Play App Signing keeps the real app-signing
key at Google. This file is your **upload key**. If you lose it, Play support can reset it, but that takes days.

**b. Add 4 GitHub secrets** (repo → Settings → Secrets and variables → Actions → New repository secret). Agents
only know the names, never the values:

- `ANDROID_KEYSTORE_BASE64`: the contents of `jade-upload.jks.b64`
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`: `upload` (or the alias you chose)
- `ANDROID_KEY_PASSWORD`

Then delete `jade-upload.jks.b64`.

**c. Play Console, internal testing track only** (round-7 decision; public tracks need title clearance first):
1. Create the Play Console developer account (one-time fee, so the owner pays) and **Create app**: name "Jade
   Tempest", game, free.
2. Accept **Play App Signing** when asked.
3. Testing → **Internal testing** → Testers: create an email list (up to 100 testers) → **Create new release** →
   upload `app-release.aab` → release notes from `store/` → **Review release** → **Start rollout to Internal
   testing**.
4. Fill in the app content forms Play requires before rollout (privacy policy URL, Data safety, content rating,
   target audience, ads = no). See `reports/compliance/` and `store/`.
5. Send testers the opt-in link from the Internal testing page.
6. Do not promote to closed, open or production until the title is cleared (STATUS "Decisions made without the
   owner", round 6/7).
