# Roadmap

Each milestone is playable from a URL on the phone and leaves `main` in a working state. Order may change only with a written reason.

**Order note (owner, M6):** Story waits until the real characters exist; levelling and Limit Break came first.

**Order note (owner, M4):** finish everything gameplay-wise first, then do the GUI. Until then, new UI is kept functional and consistent with the existing tokens, and the full visual GUI pass (menus, HUD, iconography, motion polish) happens after the gameplay milestones, as part of the Onboarding and polish milestone.

## Technology (see `decisions/0003-2d-rendering-pixijs.md`)

- **Vite + TypeScript (strict)** for build tooling.
- **PixiJS (WebGL)** for the arena, fighters, effects, and summon scenes.
- **HTML/CSS overlays** for HUD text and menus (crisp text, native scrolling, accessibility), sharing one design-token system with the in-game UI.
- **Vitest** for unit tests, **Playwright** (Android portrait emulation) for smoke tests.

## Owner action needed in M1

Enable GitHub Pages for this repository with **Source: Deploy from a branch → `gh-pages` / `(root)`** (repository Settings → Pages). The CI workflow creates the `gh-pages` branch on its first green run. Branch-based publishing is used (rather than the "GitHub Actions" source) because it lets every branch keep its own preview URL.
